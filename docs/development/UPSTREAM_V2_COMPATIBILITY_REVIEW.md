## 其他必须适配的功能

- P1：本地独立图片生成配置、人物参考图以及运行日志 Console 页不在上游发布包中。上游 `package.json` 未包含本地 `client`、`dist` 与 Console 依赖，不能整包覆盖后期待这些功能自动保留。
- P1：上游仍有中文词表式表情校准（`src/service.ts:7283` 附近）和在场判断（`normalizeScenePresenceDrafts`，7807 附近）。直接采用会恢复之前已移除的固定语义判断，需要逐条审查调用路径并接回动态审核。
- P1：V2 使用 `ScriptCommit`、事件、`deliveryActions` 和实际投递回执，旧版本按决策对象处理的审核不能机械粘贴。审核对象应对应最终正文、实际事件和授权投递；重写后重建提交，避免继续发送旧事件。还需验证流式提前发送与审核顺序。
- P1：V2 的 `sideTaskJson` 对部分 JSON 解析失败进行一次去除 `max_tokens` 的重试，适用于压缩、时间导演、日程、Overlay、Alter，不等同于本地审核接口的网络重试与严格结果校验。适配时统一总重试预算和超时，确认思考型模型的实际成本。

## 数据兼容性

上游表定义主要增加 `interlude_script_entry.embedding` 与 `interlude_fact.knowledge` 两个 JSON 字段；故事状态通过读取升级到 schemaVersion 4，旧字段具备一定容错和保留机制。源码未要求清空数据，但这只证明具备增量迁移设计，不证明生产库迁移成功。

不需要以清空两个 bot 的数据作为升级前提。即使清空，双 bot 归档和语义审核缺失仍会存在。应先修复上述 P0，再用数据库副本验证 schema 扩展、故事/参与者归属、历史读取、时间边界以及回滚。V2 写入新状态后不能只替换回旧 JS 就假定语义完全恢复，回滚应包含对应数据库备份。

## 可保留的上游改进

新的提交与回执账本有助于区分“剧情提议发送”和“消息实际到达”；原文导航、来源索引、暂停恢复、附件标记清理、OneBot 表情数字 ID、音频文件处理和模型路由兼容均值得采用。它们不能替代本地独立审核或实例隔离。

## 验证证据与限制

- 独立快照运行上游全部 298 项测试：全部通过。
- 独立快照严格 TypeScript 检查：通过；复用本地基础编译配置和已安装依赖，没有安装上游新运行环境。
- 合成双 bot 复现：调用上游真实 `getCanonicalStory`，注入只允许 bot A 的归属谓词，仍观察到 bot B 被写为 archived。使用模拟数据库，没有触及实际 bot 数据。
- 合成状态复现：输入含 `timelineBoundary` 的旧状态，经上游真实解码函数后，顶层边界消失，原值仅保存在 `extensions.timelineBoundary`。
- 未测试真实数据库迁移、Koishi 多实例启动、模型请求或新版本生产运行；上游测试通过不等于本项目升级验收通过。

## 建议实施顺序

1. 固化并保留当前已部署修复，在独立升级分支引入 V2。
2. 优先完成多实例归属和时间线边界迁移，再把动态审核接入新的提交/投递链。
3. 恢复图片生成、参考图、运行日志和管理命令，并检查配置默认值、模型路由及重试预算。
4. 用旧数据库副本验收双 bot、跨日、旧污染隔离、重复事件、发送失败/重启恢复和增量迁移；再进行合成模型链路验证。
5. 验收通过后才备份部署，保留插件与数据库配套回滚。
