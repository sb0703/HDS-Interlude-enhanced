# 审核器、恢复边界与旧规则清理

本次代码已完成，本地 240 项测试与 TypeScript 类型检查通过。最终代码已通过两条配置路线的虚构案例验收。

## P0

- 审核请求提供动态 allowedEvidenceRefs，结构纠错附本轮引用目录与对应候选原文，仍严格拒绝虚构引用和非原文片段。
- 记忆审核使用独立契约，原始叙事中的明确事件可以支持忠实概括；不要求新增细节或现实世界的独立证明。
- 普通叙事审核精简为时间、事件、传输、在场与表达各自的职责。表情矛盾不强迫时间或推进检查同时矛盾。
- 当审核结果包含用户报告时间时，再执行一次只看原始用户消息与历史时间上下文的提取复核，不给它候选剧情或首次提取结果。无依据的接收时间不能作为发生时间，失败保留不可用状态。此路径会增加一次模型调用；无时间提取结果时不增加调用。

## P1

- 显式 rebaseTimeline 记录九张表的行 ID 上界，避免旧记录靠未来发生时间绕过隔离。
- 运行时上下文、事实、待办、日程证据、向量召回和压缩只读边界之后的行，筛选在查询 limit 之前执行。管理端原始历史和归档读取仍可用。
- 重建时清空派生状态、参与者派生关系笔记、旧日程，并建立新场景与弧线；保留数据库原始行，不删除聊天。
- 重建前开始、重建后返回的压缩和日程结果不能写回。
- 本次没有在生产执行 rebaseTimeline，也没有重置两个 Bot。

## P2

- 移除未被运行时调用的固定用餐/会议/通勤/场景循环检测、重复阈值否决及固定工作日解析器；语义职责由统一审核承担，文本相似度仍仅用于检索。

- QQ 表情 ID 与名称映射属于协议数据，并非语义检测器，保留不动。
- 已删除旧辅助函数导出；外部使用者应迁移到结构化审核接口。

## 运行虚构案例

脚本只读取模型配置，不读取故事数据库、不发送 Bot 消息。运行前设置 `HDS_ROOT` 为部署根目录，其下应存在 `.local-hdsi/koishi-app`。

```sh
HDS_ROOT=/path/to/deployment node deploy/server/koishi/smoke-semantic-detection.cjs
```

- `HDS_PLUGIN_PATH`：指定候选插件包或 bundle 的绝对路径，默认读取部署目录内已安装插件。
- `HDS_CASES`：逗号分隔的案例名，用于单独复验。
- `HDS_INCLUDE_DISABLED=1`：纳入禁用实例保存的模型配置进行测试；不会启用实例，但会产生模型请求。
- `HDS_DEBUG=1`：输出虚构案例的模型文本结果，用于诊断。

语义模型仍可能误判，案例通过不代表所有自然语言表达均能正确处理。
